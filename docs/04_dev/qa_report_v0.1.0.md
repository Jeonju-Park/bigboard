## §3. 수정한 것 (이번 QA 중)

1. **터치 타깃 3건** — 랭킹 행 인물 링크 39px, 상세의 텍스트 링크 18px·15px → `.tap-safe` 유틸로 44pt 확보
2. **검색 input 높이** — 라벨은 44px인데 input 자체가 25px → `align-self: stretch`
3. **검증기 규칙 낡음** — `verify.ts` 가 대표 거래일의 옛 규칙("가장 이른 날")을 기대해 오탐 1건. 현행 규칙으로 동기화
4. (STEP 3에서) **혼합 보고서의 금액 단위 불일치** — 순증감 수량과 총 거래대금이 짝이 안 맞아 "55,530주 = 1,774억"(주당 320만원)처럼 읽히던 문제

## §4. 오탐으로 판정한 것

- **"본문이 하단 탭과 겹침"** — `position: sticky` 의 정상 동작. 맨 아래까지 스크롤했을 때 가려지는 요소 0개임을 확인
- **거래계획 5건의 단가×수량 ≠ 총액** (차이 최대 0.46%) — 제출자가 "15억"처럼 목표 금액을 반올림해 적은 **원문 그대로의 값**. 우리가 계산한 값이 아니므로 고치지 않음

## §5. 유저 확인이 필요한 3가지

1. **오픈이슈 O1** — 티커 바 존치 여부 (문서 권고는 제거)
2. **오픈이슈 O2** — 증권사 3사 선정 + 딥링크 스킴 검증
3. **오픈이슈 O3** — 공공데이터포털 키 발급 후 시세 항목 범위 (PER·PBR·배당이 안 나오면 M1 영구 제외 여부)

## §6. 측정하지 못한 것 (정직하게)

- **Lighthouse 점수** — 이 환경에 Lighthouse CLI 가 없어 실행하지 못했다. 대신 접근성 항목(접근 이름·터치타깃·alt·lang·대비 토큰)을 직접 측정했다. 배포 후 실기기에서 한 번 돌려볼 것
- **실기기 동작** — 휴대폰에서 열어보는 확인은 배포 후 유저 몫
- **성능** — 최초 로딩 gzip 약 **290KB**(disclosures 210KB 포함). 30일치 기준이며, 90일로 늘리면 재검토 필요 (설계문서 부록 A-4)
