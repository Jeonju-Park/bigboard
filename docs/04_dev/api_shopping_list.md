## A-2. 신청 방법 (5개 동일)

1. https://www.data.go.kr 우측 상단 **로그인**
2. 위 표 링크로 이동
3. 우측 상단 파란 **[활용신청]**
4. 활용목적 → **「웹 사이트 개발」**
5. 설명란에 A-3 문구 복사
6. 하단 **라이선스 표시** 동의 체크
7. **[신청]** → 자동승인

## A-3. 활용목적 문구 → §5-1 참조

## A-4. 키 가져오기 (한 번만)

**키는 API 마다가 아니라 계정당 하나다.**

마이페이지 → 데이터활용 → Open API → **인증키 발급현황** → **일반 인증키 (Decoding)** 복사

> ⚠️ **Encoding 아님.** Encoding 키를 넣으면 이중 인코딩돼 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`.
> 가장 흔한 실수라 explore 스크립트가 이 경우를 따로 감지해 안내한다.

## A-5. 키 적용

```
# pipeline/.env
DART_KEY=(이미 채워져 있음)
DATA_GO_KR_KEY=여기에_Decoding_키
```

- 따옴표 없이 그대로 붙여넣는다
- `.env` 는 `.gitignore` 에 있어 커밋되지 않는다 (확인됨)
- **키 값을 채팅·이슈·커밋에 붙여넣지 않는다**

## A-6. 확인

```bash
npm --prefix pipeline run explore:stocks
```

한 번 실행으로 ①키 활성화 ②시세 응답 필드(시총·52주) ③공직자 관보 API 형태를 모두 확인한다.

## A-7. 나중에 — GitHub Actions

배포 후 자동 수집이 돌려면 저장소 Secrets 에도 같은 값을 `DATA_GO_KR_KEY` 로 넣어야 한다
(Settings → Secrets and variables → Actions).

## 1. 금융위원회_주식시세정보 ★필수

- 링크: https://www.data.go.kr/data/15094808/openapi.do
- 신청: 활용신청 → **자동승인** (개발단계·운영단계 모두)
- 한도: **개발계정 일 10,000건**. 운영계정은 활용사례 등록 후 증액 가능
- 오퍼레이션 4개 중 **「주식 시세」** 하나만 쓰면 된다 (나머지는 수익증권·신주인수권)

**채우는 화면 필드**

| 스키마 | 화면 | 현재 |
|---|---|---|
| `Stock.prevClose` | 종목 상세 '전일종가', 피드 상세 종목 블록 | `null` (행 숨김) |
| `Stock.change` | '등락률' | `null` |
| `Stock.volume` | '거래량' | `null` |
| `Stock.marketCap` | '시가총액' | `null` |
| `Stock.high52` / `low52` | '52주 최고/최저' | `null` |
| `Stock.sparkline` | 스파크라인 1M/3M/1Y | 빈 배열 (미구현) |

**호출량 추정**

- 우리가 다루는 종목: 약 **690개** (30일 수집 기준)
- 일 1회 전 종목 갱신 → **690회/일** = 한도의 **7%**. 여유롭다
- 52주 최고/최저·스파크라인은 **과거 일자를 여러 번 조회**해야 한다
  - 1년치 = 종목당 약 250 영업일. 690종목 × 250 = **172,500회** → 한도 초과
  - **해결**: 최초 1회만 과거를 긁고(며칠에 나눠서) 이후는 하루치만 덧붙인다.
    `pipeline/.cache/` 와 같은 방식으로 종목별 시계열을 파일에 누적하면 재실행 비용이 0

⚠️ **확인 필요**: 응답에 `시가총액`·`상장주식수`가 직접 들어오는지 명세(Swagger)에서 봐야 한다.
포털 소개 문구에는 "시가·종가·고가·저가·거래량"까지만 적혀 있다. 없으면 2번 API의 상장주식수 × 종가로 계산한다.

## 2. 금융위원회_KRX상장종목정보 ★권장

- 링크: https://www.data.go.kr/data/15094775/openapi.do

**왜 필요한가**: 지금 종목명을 **DART 공시의 회사명 표기 그대로** 쓰고 있다.
공시 제출자가 적는 이름이라 정식 종목명과 다를 수 있고, 시장구분(코스피/코스닥)도 없다.
이 API 가 종목 마스터 역할을 한다.

| 스키마 | 쓰임 |
|---|---|
| 정식 종목명 | `Stock.name` 을 공시 표기 대신 정본으로 |
| 시장구분 | 코스피/코스닥 배지, 필터 |
| 상장주식수 | 시가총액 계산(1번에 없을 경우) |

## 4. 금융위원회_기업 재무정보

- 링크: https://www.data.go.kr/data/15043459/openapi.do
- 제공: 매출액·영업이익·총자산·총부채·자본금 등 재무제표 항목
- ⚠️ **PER·PBR 은 직접 주지 않는다.** 순이익·자본총계를 받아 우리가 계산해야 한다
  - PER = 시가총액 ÷ 당기순이익, PBR = 시가총액 ÷ 자본총계
  - **계산값이므로 화면에 "빅보드 계산값 · N년 재무제표 기준"을 병기해야 한다**
- 조회 키가 **법인등록번호**다. 우리는 종목코드만 갖고 있으므로 매핑이 한 단계 더 필요하다

> **대안 검토**: KRX 정보데이터시스템(data.krx.co.kr)이 PER/PBR/배당수익률을 종목별로 바로 제공한다.
> 다만 **공공데이터포털 오픈API 가 아니라 웹 조회 서비스**다 → 자동 수집은 이용약관 확인이 먼저다
> (CLAUDE.md 규칙 5: 크롤링은 robots.txt·약관 확인 보고 후 승인제, 오픈이슈 O3).
> **내 판단: 4번을 쓰고 직접 계산하는 쪽이 안전하다.** PER·PBR 이 꼭 필요한지부터 정하는 게 먼저다.

## 5. 공직자 재산공개 — API 는 있으나 형태 확인 필요 ⚠️

- **행정안전부_관보_공직자 재산 공개**: https://www.data.go.kr/data/15109164/openapi.do
- 키는 **계정당 하나**이므로 위 4개와 같은 `DATA_GO_KR_KEY` 로 쓴다

**⚠️ 이 API 가 쓸 만한지는 실제 호출 전에는 알 수 없다.**
포털 설명은 *"제목·구분·발행일자·편집구분·테마구분·발행기관·근거법령·정정여부 등 및 **원문정보**"* 라고만
적혀 있다. 두 가지 경우가 갈린다:

| 경우 | 결과 |
|---|---|
| 개인별 재산 금액이 **구조화 값**으로 옴 | `officials.ts` 를 응답에 맞춰 고치면 바로 붙는다 |
| **관보 문서 목록**(제목·발행일자·원문링크)만 옴 | 관보 원문을 파싱해야 개인별 금액이 나온다 — 큰 작업이고, 실명 재산 데이터라 오류 위험이 크다 |

또 하나: 포털에 적힌 **시간범위가 1993~2023년**이다. 최근 연도가 빠져 있으면 "연 1회 최신 자료"라는
서비스 약속을 못 지킨다 — 이것도 호출해서 확인해야 한다.

**⚠️ 엔드포인트를 아직 모른다.** 포털 상세 페이지가 요청주소를 노출하지 않아
`apis.data.go.kr/1741000/gwanbo` 등을 추측해 봤지만 전부 `NO_OPENAPI_SERVICE_ERROR`(서비스 없음)였다.
odcloud 명세 경로(`infuser.odcloud.kr/oas/docs?namespace=15109164/v1`)도 없다.

→ **필요한 것**: 포털 페이지의 **[참고문서] / [가이드 다운로드]** 를 열어
   `요청주소`(엔드포인트 URL)와 오퍼레이션 이름만 알려주면 바로 붙인다.

**지금 동작하는 경로 (권장)**: 공직윤리시스템에서 자료를 내려받아 `pipeline/data/` 에 넣는다.

```bash
# https://www.peti.go.kr/prptOptp.do 에서 자료를 받아 pipeline/data/ 에 그대로 두고
npm --prefix pipeline run officials
```

- **.xlsx 를 CSV 로 변환할 필요가 없다.** 엑셀을 직접 읽는다(ZIP+XML 파싱, 의존성 0)
- EUC-KR CSV, BOM, 제목 행이 위에 붙은 파일도 처리한다
- 열 이름은 '성명/이름', '소속/기관', '재산총액/총재산', '증권/주식' 등을 자동으로 찾는다
- **단위(원/천원)를 자동 판정하고 근거를 출력한다** — 1,000배 틀린 금액이 실명과 함께 뜨면 안 되므로
- 기준일 없는 행·합계 행은 받지 않고 사유별로 집계해 보고한다

## 5-1. 활용신청 폼 작성 내용 (복사용)

**라디오는 4개 모두 「웹 사이트 개발」.**

문구를 구체적으로 쓴 이유: 나중에 **운영계정 승격 시 심사**를 받는데, 각 API 가 화면의 어디에
쓰이는지가 분명할수록 수월하다. 금융 데이터라 "투자자문이 아님"과 "출처·기준시점 표기"를
명시해 두었다.

### 주식시세정보 (15094808)
> 전자공시(DART)의 임원·주요주주 지분 공시를 일반 이용자가 이해하기 쉽게 정리해 보여주는 개인 웹 서비스를 개발 중입니다. 공시에 등장한 종목의 전일 종가, 등락률, 거래량, 시가총액을 함께 표시해 공시 내용의 맥락을 파악할 수 있도록 하는 데 사용합니다. 1일 1회 배치로 수집하며, 화면에 출처와 기준 시점을 표기합니다. 투자자문·투자권유 목적이 아닌 정보 제공 서비스입니다.

### KRX상장종목정보 (15094775)
> 위 주식시세정보와 동일한 웹 서비스에서 종목 기준정보로 사용합니다. 현재는 공시 서류에 기재된 회사명을 그대로 표시하고 있어, 정식 종목명·종목코드·시장구분(유가증권/코스닥)·상장주식수를 정확하게 표기하기 위해 필요합니다. 상장주식수는 시가총액 계산에도 사용합니다. 1일 1회 갱신하며 출처를 표기합니다.

### 사업보고서 주요정보_배당에관한사항 (15060607)
> 전자공시(DART) 지분 공시를 정리해 보여주는 웹 서비스에서, 공시에 등장한 종목의 배당 정보를 종목 상세 화면에 표시하기 위해 사용합니다. 사업보고서 기준이므로 해당 사업연도를 함께 표기하여 이용자가 자료의 기준 시점을 알 수 있도록 합니다. 투자자문이 아닌 정보 제공 목적입니다.

### 관보_공직자 재산 공개 (15109164)
> 전자공시(DART) 지분 공시를 정리해 보여주는 웹 서비스에서, 고위공직자 재산공개 관보 정보를 함께 제공하기 위해 사용합니다. 재산공개는 연 1회 이루어지므로 화면에 공개 기준일과 출처(관보)를 반드시 함께 표기하고, 이용자가 원문을 확인할 수 있는 링크를 제공합니다. 투자자문이 아닌 공개 정보 전달 목적입니다.

### 기업 재무정보 (15043459)
> 전자공시(DART) 지분 공시를 정리해 보여주는 웹 서비스의 종목 상세 화면에서 PER·PBR을 산출하는 데 사용합니다. 당기순이익·자본총계를 받아 시가총액과 함께 계산하며, 원본 수치가 아닌 계산값임과 기준 사업연도를 화면에 함께 표기합니다. 1일 1회 갱신하며 출처를 표기합니다.

> ⚠️ 위 문구에 적은 약속(출처 표기·기준시점 표기·계산값 명시)은 **화면에서 실제로 지켜야 한다.**
> 현재 코드는 이미 그렇게 돼 있다 — `FreshnessLabel`, 설정의 데이터 출처, 랭킹의 "집계 기준" 문구.
> PER·PBR 을 붙일 때도 "빅보드 계산값 · N년 재무제표 기준"을 반드시 병기할 것.

## 6. 신청할 때 주의

1. **Decoding 키**를 `pipeline/.env` 의 `DATA_GO_KR_KEY` 에 넣으세요 (Encoding 키 아님)
2. 개발계정은 **일 10,000건**입니다. 위 계산대로면 정기 갱신은 여유롭지만,
   **과거 시계열 최초 적재는 며칠에 나눠서** 해야 합니다
3. 신청 후 **키 활성화까지 1시간 정도** 걸리는 경우가 있습니다 — 바로 안 되면 조금 기다려 보세요
4. GitHub Actions 에도 같은 값을 `DATA_GO_KR_KEY` Secret 으로 넣어야 자동 수집이 돕니다

## 7. 키가 들어오면 제가 할 일

1. `pipeline/src/stocks.ts` 구현 (수집 → `stocks.json`)
2. 종목 시계열 캐시 설계 (52주·스파크라인용, 한도 안에서)

   — 화면 코드는 이미 `null` 이 아니면 렌더하도록 돼 있어 손댈 게 없다
4. 스파크라인 SVG 컴포넌트 추가 (라이브러리 금지 — 경량 직접 구현)
