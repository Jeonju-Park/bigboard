# figma_export_handoff.md — MCP 없이 내보내기로 클로드 코드에 전달하기

> figma_to_claude_code_guide.md의 방법 B(스크린샷)+C(토큰 문서)를 실전 워크플로우로 구체화한 부록.
> MCP 대비 트레이드오프: 셋업 0·유료 플랜 불필요 ↔ 구조 정보(간격·변수 참조) 소실 → 아래 3종 세트로 보완.

---

## 원리: 3종 세트가 한 화면
| 전달물 | 담당 | 형식 |
|---|---|---|
| ① 프레임 이미지 | 생김새·배치 | PNG 2x 내보내기 |
| ② tokens.ts | 모든 값의 진실 | 이미 프로젝트에 있음 |
| ③ 스펙 노트 | 이미지↔토큰 연결 (간격·스타일 지정) | 화면당 md 10~15줄 |

이미지만 주면 클로드가 간격을 눈대중으로 추측합니다. ③이 그 추측을 차단하는 장치이며, 피그마에서 변수로 작업했다면(figma_guide.md §2) 작성이 빠릅니다 — 오토레이아웃 패널의 gap 값을 읽어 적기만 하면 됩니다.

## 1. 내보내기 규칙
- 대상: 03 Screens의 화면 프레임 + 02 Components(변형 포함 프레임 통째로)
- 설정: PNG, **2x** (1x는 작은 텍스트 뭉개짐, 4x는 불필요)
- 파일명 = 피그마 프레임명 그대로: `S1-Home-Breaking@2x.png`
- 저장 위치: `assets/figma-exports/` (프로젝트 폴더 안 — 클로드 코드가 경로로 바로 읽음)
- 아이콘·로고 등 벡터 요소는 PNG 말고 **SVG 내보내기** → `assets/brand/` (코드에 직접 임베드 가능)
- 팁: 여러 프레임 일괄 내보내기는 프레임 다중 선택 후 Export. 상태 변형(빈/에러)도 각각

## 2. 스펙 노트 작성 (화면당 1개, 10~15줄)
`assets/figma-exports/S1-Home.spec.md` 형식. 이미지에서 안 보이는 것만 적는다:

```
# S1-Home 스펙
- 좌우 여백 space/5(20) 고정, 섹션 간 space/10(40)
- 세그먼트: L2/title-s, 선택 = ink 밑줄 2px, 비선택 = gray/500
- 공시 카드: DisclosureCard 컴포넌트. 카드 간 space/3(12), 날짜 그룹 간 space/6(24)
- 카드 내부: 총액 = Numeric 17/700 + 마커, 단가×수량 = L4/caption gray/500 (총액보다 약하게)
- 필터 칩: 선택 시 배경 bg/secondary, 보더 없음
- 리스트 하단 도달: L3 안내 + L5 micro 위트 1줄
- 터치 영역 최소 44px, 스크롤 시 앱바 고정
```
규칙: 값은 반드시 토큰명으로(raw px·hex 금지 — 여기서 raw로 쓰면 코드에도 raw로 박힘). 계층은 L1~L5 이름으로.

## 3. 클로드 코드 프롬프트 템플릿
```
assets/figma-exports/S1-Home-Breaking@2x.png 를 보고 /home 화면을 구현해줘.
- 스펙: assets/figma-exports/S1-Home.spec.md 를 우선 적용 (이미지와 충돌 시 스펙이 우선)
- 값은 src/theme/tokens.ts 토큰만. 이미지에서 눈대중으로 잰 px 사용 금지 —
  스펙에 없는 간격은 추측하지 말고 나에게 질문해줘
- 기존 shared/components 재사용
완료 후: 구현 화면 스크린샷 찍는 법 안내 → 내가 원본 PNG와 비교할 것
```
"스펙에 없으면 질문" 조항이 중요합니다. 이게 없으면 클로드는 조용히 추측하고, 미묘한 어긋남이 화면마다 누적됩니다.

## 4. 검수 루프 (MCP 없을 때 더 중요)
1. 구현 후 브라우저 캡처 ↔ 피그마 PNG를 나란히 비교
2. 차이 발견 시 두 이미지를 함께 첨부:
   "두 이미지 차이를 표로 정리하고 토큰 기준으로 수정해줘. 카드 간격은 space/3이어야 해"
3. 수정 확인 → commit. 화면당 이 루프 1~2회면 수렴

## 5. 한계와 판단 기준
- 이 방식의 비용: 화면당 스펙 노트 5~10분 + 검수 루프 1회 추가 [추정]. 화면 10개면 감내 가능한 수준
- MCP로 갈아탈 시점: 컴포넌트 변형이 많아지거나(디자인 시스템 확장), 디자인 수정→재구현 왕복이 잦아질 때. 그때는 셋업 1회 비용이 바로 회수됨
- 하지 말 것: 피그마 공유 링크만 던지기(클로드 코드는 로그인된 피그마 웹을 볼 수 없음), 스펙 노트 없이 이미지만 주기(추측 유발), 1x 내보내기(텍스트 판독 불가)

## 강의 관점 메모
MCP 방식과 이 방식을 같은 화면으로 비교 시연하면 "구조 정보가 왜 중요한가"를 보여주는 최고의 교보재가 됩니다 — 이미지만 준 결과물의 하드코딩·간격 오차를 diff로 보여주는 구성 추천. [추정]
