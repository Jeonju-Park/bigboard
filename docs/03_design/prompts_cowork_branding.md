# prompts_cowork_branding.md — 클로드 코워크 브랜딩 세션 프롬프트

> 사용법: 클로드 코워크에서 bigshot-radar 폴더를 열고 아래 전문을 붙여넣기.
> 이 세션이 끝나면 미결정 3건(서비스명 O7 / 마커 컬러 / Display 폰트)이 확정되고 assets/brand/가 채워진다.
> 완료 후 이 파일과 산출물은 docs/03_design/에 보관.

---

```
이 폴더는 "큰손레이더(가칭)" 프로젝트입니다. 오늘은 브랜딩 세션입니다.
진행 범위: 서비스명 → 브랜드 원칙 → 메인 색상 확정 → 폰트 확정 → 로고 → 파비콘.
각 STOP 지점에서 반드시 멈추고 내 승인을 받은 뒤 다음으로 진행하세요.

== STEP 0. 컨텍스트 로드 (먼저 읽기) ==
1) docs/03_design/bx_designsystem_source_bigshot_radar.md — 디자인 방향("개표방송 스튜디오")과 §9 미결정 사항
2) docs/decisions_log.md, docs/04_dev/ia_snapshot.md — 서비스 정의
3) docs/01_research/feasibility_legal_kr.md §2 — 금지 워딩(추천/시그널 등). 브랜드 카피에도 동일 적용
4) claude_project/PROJECT_INSTRUCTIONS.md — 출처 표기 규칙((명확하지 않은 출처)/[추정])
읽은 뒤 "이 브랜드가 지켜야 할 제약 5줄 요약"으로 시작하세요.

== STEP 1. 서비스명 ==
후보 6개를 만들되 3계열로: ①직관 계열(큰손레이더처럼 기능이 바로 읽힘) ②개표방송 은유 계열(중계/속보/개표 어휘) ③짧은 고유명 계열(2~3음절, 브랜드화 용이).
각 후보마다: 한 줄 논리 / 발음·기억 용이성 / 검색 시 기존 서비스·상표 충돌 여부(웹 검색으로 확인, 앱스토어·플레이스토어 동명 앱 포함) / .kr·.com·.app 도메인 가용성(웹 조회 가능한 범위에서, 불확실하면 표기) / 리스크.
주의: 상표 등록 여부는 키프리스(kipris.or.kr)에서 내가 최종 확인해야 함을 명시하고, 확인 절차를 3줄로 안내.
비교표 + 추천 1개(이유 2줄) 제시.
[STOP — 서비스명 승인 대기]

== STEP 2. 브랜드 원칙 ==
확정된 이름으로 작성: 브랜드 스테이트먼트 1줄 / 톤 키워드 4개 / 페르소나("농담은 하지만 숫자는 안 틀리는 캐스터" 계승·발전) / 보이스 DO 3·DON'T 3(법적 금지 워딩 목록 통합) / 위트 사용 규칙(micro 11px 레이어에서만 — 기존 규칙 유지) / 네이밍 확장 규칙(기능·화면 이름 지을 때의 어휘 톤).
→ docs/03_design/brand_principles.md 로 저장.

== STEP 3. 메인 색상 확정 ==
bx 문서 §9의 3후보(방송 옐로우 #FFD338 / 민트 #3ECFB2 / 오렌지 #FF7A3D)를 실제 사용 맥락 3곳(마커 하이라이트, 랭킹 1위 강조, 로고 포인트)에서 비교. 각 후보의 흰 배경 위 인상, 국장 시맨틱(매수 레드 #D93B3B·매도 블루 #2563A8)과의 간섭 여부, WCAG 대비(마커 위 ink 텍스트 기준) 검토.
추천 1개 + 이유. 확정되면 bx 문서 §2와 §9를 갱신하고 gray 스케일·시맨틱은 유지.
[STOP — 색상 승인 대기]

== STEP 4. 폰트 확정 ==
Display 후보 Paperlogy vs Gmarket Sans: 눈누(noonnu.cc)와 배포처에서 라이선스(상업·웹폰트·앱 임베딩 허용 범위)를 웹으로 확인하고 출처 링크와 함께 비교. 임베딩 조건이 다르면 그것이 결정 요인(웹앱+추후 네이티브 앱 둘 다 필요).
Body는 Pretendard, Numeric은 IBM Plex Mono로 유지 — 다운로드 출처(공식 GitHub/저장소)와 웹폰트 로딩 방식(가급적 CDN, 파일 동봉 시 라이선스 사본 필수)을 정리.
→ assets/brand/fonts/ 에 폰트 확보 절차 README.md 작성(파일 직접 다운로드가 가능하면 수행하고, 라이선스 전문 동봉).
[STOP — 폰트 승인 대기]

== STEP 5. 로고 ==
확정된 이름·색으로 SVG 로고 3안을 코드로 직접 제작(래스터 생성 금지, 벡터만):
- 공통 제약: 플랫·단색+마커 색 포인트, 그라데이션·그림자·3D 금지, 32px로 축소해도 식별 가능한 심볼
- 모티브 방향: A) 레이더/스코프 B) 개표방송 그래픽(체크·집계 바) C) 워드마크 중심+마커 하이라이트
- 각 안: assets/brand/logo/draft/[a|b|c].svg + 심볼 단독 버전 + 흰 배경/secondary 배경 미리보기 HTML 1개(assets/brand/logo/preview.html — 브라우저로 열어 비교)
- 각 안의 모티브 논리와 축소 내성 자평 포함
[STOP — 로고 안 선택 대기. 선택 후 파인튜닝 1라운드]

== STEP 6. 파비콘·앱 아이콘 ==
확정 심볼로 제작(변환 스크립트 작성·실행):
- favicon.svg / favicon-32.png / favicon-16.png / apple-touch-icon-180.png / icon-512-maskable.png(세이프존 준수)
- 웹앱 반영용 index.html <head> 스니펫 + manifest 스니펫을 assets/brand/favicon/README.md에
- 산출: assets/brand/favicon/
- 32px 실크기 렌더 캡처 또는 미리보기 HTML로 식별성 확인 결과 보고

== STEP 7. 마무리 ==
1) docs/03_design/bx_brand_final.md — 이 세션의 확정값 총정리(이름·원칙·색·폰트·로고 사용 규칙: 클리어스페이스=심볼 높이의 1/2, 최소 크기, 금지 사용례 3개)
2) bx_designsystem_source_bigshot_radar.md의 §9 미결정 항목을 확정값으로 갱신, 서비스명 가칭 표기 일괄 정리
3) docs/decisions_log.md에 오늘 결정 추가 (O7 해소 기록 — 노션 오픈이슈는 내가 직접 갱신)
4) git 사용 가능하면 commit "branding: name, color, font, logo, favicon"

== 공통 규칙 ==
- 이모지 사용 금지(문서·로고·카피 전부), 안티 AI 체크리스트(bx 문서 §8) 준수
- 모든 외부 사실(라이선스·상표·도메인)은 출처 링크, 미확인은 (명확하지 않은 출처), 추측은 [추정]
- 내 승인 없이 STOP을 넘어가지 말 것. 승인 전 다음 단계 산출물을 미리 만들지 말 것
```
