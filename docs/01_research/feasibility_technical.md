# 기술 타당성: 무엇이 되고 무엇이 안 되는가

> 조사일: 2026-07-30

## 1. 증권사 연동 (자동매매·계좌 연결)

### 1.1 개인용 오픈API — 가능 (단, 본인 계좌만)
- 한국투자증권 **KIS Developers**: REST API + 실시간 웹소켓, 국내/해외주식 주문·조회, 모의투자 환경 제공. 2022.4부터 국내 최초 REST 오픈API. Rate limit 초당 20건.
- 기타: 키움 OpenAPI+, LS증권 xingAPI, 대신 크레온 등 (COM/OCX 기반, Windows 종속)
- 출처: KIS Developers https://apiportal.koreainvestment.com/about-howto · wikidocs https://wikidocs.net/165185

### 1.2 서비스용(고객 계좌 연동) — 라이선스 벽 ❌
KIS Developers 공식 안내 원문 요지:
> 주문/계좌 연동 고객 서비스를 제공하려는 법인은 별도 제휴계약 필요. **제도권 금융회사(투자일임업·투자자문업)가 아닌 핀테크사는 제휴 불가.**

→ 기술 문제가 아니라 제휴 조건이 라이선스를 요구. 법률 문서(feasibility_legal_kr.md) §1과 동일 결론.

### 1.3 v1에서의 "따라하기" UX 대안
- 공시 카드에서 **증권사 앱 딥링크**(종목 화면)로 연결 → 사용자가 본인 앱에서 직접 주문. 실행 주체가 사용자이므로 일임 아님.
- 각 증권사 딥링크 스킴은 비공식·변동 가능 [추정] → 개발 단계에서 토스증권/삼성증권/키움 등 상위 3개만 검증해 지원.

## 4. 권장 스택 (1인 + Claude Code 기준)
- **수집**: Python 스케줄러(cron) → DART OpenAPI 폴링(장중 30분 간격) → Supabase(Postgres)
- **가공**: 공시 원문 → 구조화(종목/보고자/사유/수량/단가) → 이벤트 카드 생성. LLM 요약은 선택(비용 주의)
- **앱**: React Native + Expo (03_DEVELOPMENT_GUIDE 권장 조합) + FCM 푸시
- **웹/랜딩**: Framer 또는 Claude Design (PSF 검증용 사전예약 랜딩 우선)
- 리스크: DART 폴링 지연·공시 정정(정정공시 흔함) 처리 로직 필요 — QA 단계 체크리스트에 포함
